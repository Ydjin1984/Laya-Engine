# Интеграция с ZCode

Плагин **`davinci-laya-decisions`** встраивает локальный движок Laya в точки
контроля ZCode (агентный цикл): гейт риска перед опасными вызовами, ledger
изменений, проверка доказательств завершения, ранжирование контекста и
10 MCP-инструментов типизированных решений. Вместе с плагином ставится **навык**
(`laya-decision-workflow`), который объясняет модели, когда инструменты
окупаются, а когда нет.

**Канонический источник:** <https://github.com/Ydjin1984/davinci-laya-zcode>
(публичный репозиторий-маркетплейс; плагин + навык + команды + MCP одним пакетом).

## Установка (2 минуты)

### Вариант A — через UI ZCode (рекомендуется)

1. **Settings → Plugin Management → Discover → «+» → GitHub repository**
   → `Ydjin1984/davinci-laya-zcode`.
2. Включить плагин **«DaVinci × Laya: локальные решения»**.
3. Запустить **новую сессию** ZCode (хуки, команды, навык и MCP-сервер
   подхватываются при старте), при первом вызове MCP-инструмента разрешить доступ.
4. Проверить: команда **`/laya-status`** в чате.

### Вариант B — скриптом из этого репозитория

```bash
./scripts/install-plugin.sh          # Linux/macOS (клон в ~/.zcode/plugin-workspace)
```
```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\install-plugin.ps1   # Windows
```

Скрипт клонирует маркетплейс, раскладывает плагин в локальное рабочее
пространство ZCode, регистрирует его в `marketplace.json` (с бэкапом) и печатает
шаги включения. На Linux/macOS он дополнительно собирает лаунчер хуков
(`go build` или pass-through обёртка), потому что в репозитории лежит
Windows-бинарь.

## Требования

| Что | Зачем |
|---|---|
| Node.js ≥ 20 | хуки, MCP-сервер и CLI плагина |
| Запущенный движок на `127.0.0.1:8095` | активные функции; без движка плагин работает в пассивном режиме (fail-open) |
| Go (только Linux/macOS) | собрать лаунчер хуков из `tools/hook-launcher` (иначе ставится pass-through обёртка — работает, но чуть медленнее) |

Движок поднимается из этого репозитория: `./scripts/laya.sh start` /
`start-laya.cmd`.

## Что делает плагин

| Компонент | Событие ZCode | Поведение по умолчанию |
|---|---|---|
| **RiskGate** | `PreToolUse` (Bash/Write/Edit) | `shadow`: считает риск (детерминированные правила + Laya), пишет метрики, разрешения не меняет |
| **EvidenceLedger** | `PostToolUse` / `PostToolUseFailure` | ведёт факты: изменённые файлы, запущенные проверки и их коды, нерешённые ошибки |
| **DoneGate** | `Stop` | `report`: замечает «код менялся — тесты не запускались»; в режиме `block` один раз возвращает задачу на проверку |
| **TaskRouter** | `UserPromptSubmit` | `log`: классифицирует задачу (fast/balanced/deep); в `advise` добавляет строку-рекомендацию. Модель не переключает |
| **ContextSelector** | MCP-инструменты | ранжирование попаданий, триаж логов, отбор артефактов с доступом к вытесненному через `laya_get_chunk` |

Плюс **10 MCP-инструментов** (`laya_decide`, `laya_classify`, `laya_score`,
`laya_batch`, `laya_search_relevant`, `laya_log_triage`, `laya_context_pick`,
`laya_get_chunk`, `laya_rank_diff`, `laya_health`) и **7 команд**
(`/laya-status`, `/laya-all`, `/laya-mode`, `/laya-triage`, `/laya-search`,
`/laya-review`, `/laya-bench`).

## Измеренный эффект

- Гейты: **24/24** высокорисковых вызовов подняли вопрос, **0/21** ложных
  срабатываний на безопасных; **0 токенов** контекста в shadow-режиме.
- Большой лог (7000 строк / 358 КБ): **−48 % входных токенов**
  (992 037 → 513 614) и **−58 % пика контекста** (223 663 → 94 455) при том же
  времени и полноте ответов 26/26.
- Правило окупаемости: инструмент отбора оправдан, только если он **заменяет**
  чтение целиком. Для артефактов, влезающих в одно чтение, читайте напрямую.

Методика, сырые журналы и оговорки — в репозитории плагина:
`plugins/davinci-laya-decisions/docs/AB-RESULTS.md`.

## Три принципа (важно понимать до включения активных режимов)

1. **Вероятность ≠ доказательство.** Детерминированные правила и факты
   (`git status`, коды возврата тестов) имеют приоритет. Laya никогда не
   расширяет разрешения: на выходе гейта нет `allow`.
2. **Fail-open.** Laya недоступна, таймаут, битая схема ответа — ZCode работает
   штатно.
3. **Измерять, а не обещать.** Решения пишутся в локальные метрики; активные
   режимы (`ask`/`block`/`advise`) включаются после просмотра чисел.
