# Политика безопасности / Security Policy

## Модель угроз

Laya Engine — **локальный** сервис. Он слушает только loopback (`127.0.0.1:8095`
по умолчанию), не ходит в сеть в рантайме и не принимает данные из интернета.
Основные риски смещены в сторону «что уходит в модель» и «что делает клиент по
ответам модели».

| Риск | Кто закрывает | Как |
|---|---|---|
| Сервис выставлен наружу (`-addr 0.0.0.0:8095`) | пользователь | не выставляйте. Наружу нужен reverse-proxy с аутентификацией и пониманием, что запросы содержат ваш текст. |
| Утечка секретов в модель | клиент (плагин ZCode маскирует до отправки: bearer, `sk-`/`ghp_`, AKIA, `password=`, PEM, cookie, `.env`) | маскируйте секреты **до** вызова API; лог строк состояния не ведите. |
| Ответы модели влияют на решения как «истина» | клиент | вероятность ≠ доказательство: детерминированные правила и факты имеют приоритет; Laya никогда не расширяет разрешения. |
| Обрезанное состояние («уверенно не по делу») | клиент | проверяйте `budget.state_truncated`, `state_dropped`, `collapsed`; при ненулевом — ответ не должен влиять на решения. |
| Подмена весов | оба | каждый ответ несёт `checkpoint` (sha256 весов). Клиенты обязаны привязывать пороги к чекпоинту. |
| Битый/подменённый файл при установке | скрипты | `scripts/fetch-*` проверяют SHA-256 по `models/model-manifest.json`. |

## Что не поддерживается

- Многопользовательский доступ по сети: сервис не аутентифицирует запросы.
- Публичный интернет: сервис не рассчитан на недоверенный ввод.

## Сообщить об уязвимости

Не открывайте публичный issue. Напишите на GitHub: **@Ydjin1984**
(или через [Security Advisory](https://github.com/Ydjin1984/Laya-Engine/security/advisories/new)).

Ответ — в течение 7 дней. В обращении укажите: версию/чекпоинт (`/info`),
команду воспроизведения, ожидаемое и фактическое поведение.
